How to build this in SharePoint

All of it is buildable with out-of-the-box web parts, a theme and list formatting. Nothing here needs a developer. Three items need a tenant or site-collection admin, and they are marked.

What SharePoint will and won't let you do

Worth knowing before anyone promises a design: you cannot inject custom CSS or JavaScript into a modern SharePoint page. The classic master-page and alternate-CSS route does not apply. What you get instead:

  • Theme — primary, accent and neutral colours applied site-wide via Change the look, or centrally from Brand Center.
  • Fonts — Brand Center font packages let you upload .woff2 files and set a display + content font. This is how Archivo / Source Sans 3 get in. (Needs admin.)
  • Section backgrounds — None, Neutral, Soft, Strong. The whole visual rhythm of the design above is built from alternating these four.
  • A vertical section — the right-hand rail. One per page, always the last column.
  • List formatting JSON — column and view formatting. This is where the progress bars, the RAG chips and the issue-age chart come from, and it needs no admin rights at all.
  • SPFx web parts — full design control, but a real development and deployment cycle. Skip for now.
  • Embed web part — iframes only, from domains on the site collection's HTML Field Security allow-list. Script tags are stripped. (Allow-list needs admin.)

Decide this first: is it staying a private group site?

Your current site is a private group team site. The “Being audited” path and everything aimed at the wider business only pays off if people outside Internal Audit can open it. Either open read access to the whole organisation and keep working files in a separate closed library, or split into two sites: a public-facing Internal Audit communication site and this private team site behind it. Decide before you build — it changes navigation, permissions and how you write every page.

Generate at aka.ms/themedesigner from the primary below, then apply with Add-SPOTheme or paste into Brand Center. Primary and body text are the two inputs that matter.

Accent       #1D8FA3   hover and interactive states
Body text    #14232B   near-black, slightly cool

Sequence

Week 1 — half a day

Theme and skeleton

Apply the theme. Rebuild the home page sections in the order above, with placeholder text. Fix the top navigation to the seven items in the header — your current navigation is the library structure, which is not how anyone thinks about their work.

Week 1–2 — two days

Icons, links and copy

Commission or draw the six Quick Links icons as one set. Write the descriptions — one sentence each, saying what the person gets, not what the thing is called. Verify every link opens for someone who is not you.

Week 2–3 — two days

The three "Start here" paths

This is the real work and it is content, not design. The “Being audited” column will not exist yet; write it. It is the highest-value page on the site and the one that makes the wider business link to you.

Week 3–4 — three days

Make it live

Build two SharePoint lists — Engagements and Issues — and format their views into the progress card and the age chart. Static pages get visited once. A page showing this week's real numbers gets visited weekly, which is the whole objective.

Ongoing

Ownership and measurement

Name an owner per section and a review date. Turn on site usage analytics and watch which Quick Links get clicked after a month — drop or rewrite the bottom two. An intranet page dies from unowned stale content, not from bad design.

Build the lists properly now, and they migrate later

You mentioned wanting a custom in-house platform eventually. The Engagements, Issues, Requests and CPE lists you create in phase four are that platform's first data model. Give them real columns with proper types — choice fields, date fields, person fields, a stable ID — instead of free text, and the migration later is an export rather than a re-keying exercise. Treat this SharePoint build as the prototype of the data model, not just as a website.

Three things to raise with your admin

  • Brand Center font package — needed for the custom typography. Without it everything renders in Segoe UI, which still works but loses a lot of the character.
  • HTML Field Security allow-list — only if you want to embed a Power BI report or TeamMate+ dashboard as an iframe.
  • Site audience / permissions — the private-group question above.
